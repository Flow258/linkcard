# LinkCard

A no-code digital business card builder — create a card, publish it to
`linkcard.site/you`, and share it with a link or QR code.

This is the **MVP** described in the project plan: the full create → template →
customize → username → publish flow, a public card page, a dashboard, QR
codes, and one-tap "Save contact" (.vcf download).

## Getting started

```bash
npm install
npm run dev
```

Then open http://localhost:3000.

## How this MVP is built (important to know)

There is **no backend yet**. Every card is saved to `localStorage` in your
own browser (see `lib/storage.ts`). That means:

- Publishing a card and opening `linkcard.site/dave` works great on the
  same device/browser you created it in.
- It will **not** be visible from a different browser or device — there's
  nowhere else for the data to live yet.
- Clearing your browser storage deletes your cards.

This is intentional: it lets you build and demo the entire product
experience — the editor, templates, customization, username system, QR
codes, sharing, vCard export — before investing in a backend. It's Phase 1
+ 2 of the roadmap in the original plan.

`lib/storage.ts` is written as a small, isolated module with the exact
shape a real API client would have (`getProfile`, `saveProfile`,
`isUsernameTaken`, `listProfiles`, `deleteProfile`). To move to Phase 3
(real public URLs from any device):

1. Stand up the Cloudflare Worker + D1 API described in the original plan
   (`/api/profile/:username`, etc.).
2. Replace the bodies of the functions in `lib/storage.ts` with `fetch`
   calls to that API.
3. Nothing else in the app needs to change — no component talks to
   `localStorage` directly.

QR codes are generated by hitting the free `api.qrserver.com` image API
(see `components/card/QRCode.tsx`), so QR rendering needs internet access.
Swap in the `qrcode` npm package and a `<canvas>` if you want that to work
fully offline.

## Project structure

```
app/
  page.tsx                 Marketing homepage
  create/page.tsx          The 5-step card wizard
  dashboard/page.tsx       List / edit / publish / delete your cards
  analytics/page.tsx       Placeholder for Phase 5
  [username]/page.tsx      Public card page (linkcard.site/username)

components/
  card/                    ProfileCard, SocialLinks, ContactButtons, QRCode
                           — shared by both the editor preview and the
                           public page, so what you design is what you get
  editor/                  The five wizard steps + shared form bits

lib/
  types.ts                 Profile / link / color / layout types
  templates.ts             The 9 starting templates (4 categories)
  storage.ts               Persistence layer (localStorage today, API later)
  username.ts              Validation, reserved words, suggestions
  vcard.ts                 .vcf generation for "Save contact"
  linkMeta.ts              Icon + label per link type
  utils.ts                 IDs and URL helpers
```

## What's deliberately out of scope for this MVP

Straight from the original roadmap — these are the natural next phases,
not oversights:

- **Accounts/auth** — right now "your cards" just means "cards saved in
  this browser." Add email/password (and optionally Google/GitHub) once
  there's a backend to attach them to.
- **Real analytics** — views, link clicks, QR scans, contact downloads.
  Needs a backend to record events; the page is stubbed at `/analytics`.
- **Multiple cards per account, custom domains, removing "Powered by
  LinkCard," premium templates** — these are the monetization features
  from the plan (Phase 6) and depend on accounts existing first.
- **Skills / Services / Projects sections, resume upload, printable QR
  business cards, NFC, PWA/offline editing** — all listed as "later" in
  the original plan; the data model (`Profile`) is intentionally easy to
  extend with new optional sections when you get there.

## Tech

Next.js 14 (App Router) · React 18 · TypeScript · Tailwind CSS ·
lucide-react icons. No database, no auth, no paid services required to
run this MVP.
