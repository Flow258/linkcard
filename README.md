# LinkCard

A no-code digital business card builder — create a card, publish it to
`linkcard.site/you`, and share it with a link or QR code.

This build covers the full MVP flow (create → extras → template →
customize → username → publish), a public card page, a dashboard, QR
codes, one-tap "Save contact" (.vcf download) — **plus** the optional
sections from the original plan (skills, projects, services, resume link,
every link type) and a real, deployable backend.

## Getting started

```bash
npm install
npm run dev
```

Then open http://localhost:3000. It works immediately with **no setup** —
see "Two ways to run this" below.

## Two ways to run this

### 1. Zero-setup (default)

If you don't set `NEXT_PUBLIC_LINKCARD_API_URL`, cards are saved to this
browser's `localStorage` (`lib/localBackend.ts`). Great for trying the
product or developing the editor UI, but a published card is only visible
on the device that created it.

### 2. Real backend (cross-device)

Deploy the Cloudflare Worker + D1 API in `/worker` (see
`worker/README.md` — takes about five minutes on a free Cloudflare
account), then point the app at it:

```bash
# .env.local, in this folder
NEXT_PUBLIC_LINKCARD_API_URL=https://linkcard-api.you.workers.dev
```

Restart the dev server. Now `linkcard.site/you` works from any device,
your dashboard lists your cards by a locally-remembered "owner token"
instead of raw localStorage, and `/analytics/[username]` shows real view
and download counts. Nothing in the app's components changed to make this
work — `lib/data.ts` just swaps which backend it talks to
(`lib/localBackend.ts` vs `lib/apiBackend.ts`), both of which implement
the same interface in `lib/backend.ts`.

QR codes are generated by hitting the free `api.qrserver.com` image API
(see `components/card/QRCode.tsx`) either way, so QR rendering needs
internet access regardless of which backend you use. Swap in the
`qrcode` npm package and a `<canvas>` if you want that fully offline too.

## Project structure

```
app/
  page.tsx                    Marketing homepage
  create/page.tsx             The 6-step card wizard
  dashboard/page.tsx          List / edit / publish / delete your cards
  analytics/[username]/       Real view/click/download counts (needs the API backend)
  [username]/page.tsx         Public card page (linkcard.site/username)

components/
  card/                       ProfileCard, SocialLinks, ContactButtons, QRCode
                              — shared by the editor preview and the public
                              page, so what you design is what you get
  editor/                     The six wizard steps + shared form bits
                              (Details, Extras, Template, Customize,
                              Username, Publish; LinksManager handles every
                              link type)

lib/
  types.ts                    Profile / link / color / layout / section types
  templates.ts                The 9 starting templates (4 categories)
  backend.ts                  Shared interface both backends implement
  localBackend.ts             localStorage backend (default, zero setup)
  apiBackend.ts                Worker API backend (used when configured)
  data.ts                     Picks a backend; the only import point the UI uses
  ownerTokens.ts              Per-card edit tokens for the API backend
  analytics.ts                Fire-and-forget event tracking (no-ops locally)
  username.ts                 Validation, reserved words, suggestions
  vcard.ts                    .vcf generation for "Save contact"
  linkMeta.ts                 Icon + label per link type
  utils.ts                    IDs and URL helpers

worker/                       Cloudflare Worker + D1 API (see worker/README.md)
```

## What's in vs. still deliberately out

**In this build:** every link type (GitHub/LinkedIn/Portfolio quick slots
plus Instagram/YouTube/WhatsApp/Telegram/Discord/custom via the link
manager), Skills, Projects, Services, a resume link, per-card sections
you can toggle on/off, public/private email & phone, username rename,
and a working cross-device backend with lightweight analytics.

**Still out of scope**, straight from the original roadmap's later
phases:

- **Full accounts** — no email/password login. "Your cards" means
  "cards whose owner token this browser holds." Good enough for one
  person's own cards; add real auth (see `worker/README.md`) if you need
  a login screen or multiple people managing the same account.
- **Multiple cards per *account*, custom domains, removing "Powered by
  LinkCard," premium/paid templates** — the monetization features
  (Phase 6 in the plan) depend on real accounts existing first.
- **Testimonials, NFC writing, PWA/offline editing, printable
  front-and-back QR business cards** — the data model is easy to extend
  when you get there; these just weren't built yet.

## Tech

Next.js 14 (App Router) · React 18 · TypeScript · Tailwind CSS ·
lucide-react icons · Cloudflare Workers + D1 (optional backend). No paid
services required to run either mode.
